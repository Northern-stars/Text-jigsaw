# 标签初步核验后的 NAR 管线检查（2026-11-16）

前提：用户人工审查认为标签大体正确。以下记录排查时的特征和结构问题，不把少量人工检查视作整个数据集已被证明无误。checkpoint 未修改。

修复状态：问题 1 已修复。NAR 输入现为“任务说明及全部 OCR → Panel 0 标签及图片 → … → Panel K-1 标签及图片”，让所有被池化的图片位置都能读取任务和显式文字。下文问题 1 描述修复前状态；其余结构问题尚未在本次修复中调整。原 checkpoint 参数格式可加载，但输入条件已变化，新旧评测和训练结果需要分别记录。

## 1. 确认：后置任务文本和 OCR 没有进入图片 readout

`Solver/agent/mangazero_qwen_vl_nonautoregressive.py` 的 `prepare_inputs` 将所有图片放在前面，首尾说明和 OCR 放在后面。`encode_panels` 读取语言模型最后层 hidden states，`_pool_per_panel` 只平均池化 `<|image_pad|>` 对应位置。

Qwen 语言层的因果掩码阻止较早位置读取后续 token。因此显式提供的 OCR 和任务说明不影响当前提取的图片 hidden states。图片中嵌入的文字仍可能由视觉编码器识别，不能说模型完全没有文字线索。

用安装的 Transformers 4.57.6 的真实 `Qwen2_5_VLTextModel` 类，随机初始化一个 2 层、24 维的小模型，输入模拟图文 token 的 embeddings 验证：

| 改动或梯度检查 | 最大 hidden 差异 / 梯度范数 |
| --- | ---: |
| 改变后置文字，读取前面图片位置 | 0 |
| 改变前置文字，读取图片位置 | 0.02436 |
| 图片 readout 对后置文字 embeddings 的梯度 | 0 |
| 图片 readout 对前置文字 embeddings 的梯度 | 0.02291 |

这是因果可见性的验证，不是对预训练 Qwen 的理解能力测试；没有加载视觉塔、真实图片或基础权重。

改进方向：先把任务说明和对应 OCR 放到它们应影响的图片之前，并明确 panel 编号和角色；更完整的对照是在所有图文之后增加带 panel 标识的汇总 token，再读取这些位置。单纯在 prompt 结尾增加更多说明无法解决当前 readout 的可见性。

## 2. 确认：decoder 本身没有显式首尾角色条件

Set encoder 不含输入位置或角色 embedding；cross-attention 把所有 memory 当作集合。最后选择候选时虽排除输入 0 和 K-1，但“不能选择”不等于在推理表示中识别谁是起点、谁是终点。

保持中间 memory 不变，仅交换首尾 memory，比较中间 logits：

- 新初始化 decoder 最大差异：`3.43e-7`。
- 保存的 checkpoint decoder 最大差异：`2.38e-7`。

这符合不带角色条件的集合注意力的置换性质。它并不证明完整 Qwen 管线完全无法知道端点身份：Qwen 特征可能隐含输入位置和前缀上下文；但目前模型依赖这种隐含信号，后置首尾说明也无法影响图片 readout。

改进方向：增加 START / MIDDLE / END 角色编码，或分别从起点和终点生成条件向量。中间 panel 不应使用真实阅读位置作为输入。

## 3. 确认：当前实现与参考方案存在关键差异

对照 `third_party/nonautoregressive-sentence-ordering-main/transformers_step/modeling_bert.py` 和 `encoder.py`：

| 内容 | 参考实现 | 当前实现 |
| --- | --- | --- |
| 输出位置条件 | 固定正弦位置编码经 `pol` 线性变换 | 可学习 query，初始化标准差 0.02 |
| 行方向训练 | 屏蔽 GT 前缀中已出现的候选 | 所有中间候选同时竞争 |
| 列方向权重 | 额外除以样本的 `num_sen - 1` | 默认列 CE 与行 CE 等权 |
| Backbone/readout | BART 路径上的句子位置特征 | Qwen 因果语言层图片位置均值池化 |

这些是方案差异，并非每项都可直接归类为实现错误。尤其不能以“参考架构能训练”为由，认为当前版本理应具有相同优化表现。GT 前缀 mask 仅应在训练监督目标中使用，不能在测试时读取 GT。

Checkpoint 先前探针已发现 query 输出趋同和 tanh 饱和。本次独立合成 memory 探针中，新初始化的中间投影 query 余弦相似度约 `0.93915`，checkpoint 约 `0.99983`。精确数值随探针 memory 改变，但退化趋势一致。

改进方向：把固定位置条件、现有 query、稳定打分头分别做对照。若引入固定位置，也应施加于输出阅读位置，而不是把 GT 中间顺序注入输入。

## 4. 确认：趋同后有一个不依赖标签错误的停滞机制

考虑退化极限：所有输出位置共享相同的 panel 偏好向量。每个有效排列包含每个中间 panel 恰好一次，因此一个没有位置区分能力的打分器，无法通过全局偏好某个 panel 改善排序。行 CE 在均匀偏好处最小，列 CE 因各位置相同也无法区分位置。

脚本使用一条合法且非平凡的 GT 排列验证：

- 行列 loss：`2.7725887298583984`。
- 理论基线：`2 × ln(4) = 2.772588722239781`。
- 对共享 panel 偏好参数的梯度范数：`0`。

这解释了为什么标签正确也可能停在该数值。它没有证明真实 decoder 的所有梯度严格为零，也没有证明完整模型无法从退化处逃离；位置独立参数仍可能提供打破对称性的方向。此前 checkpoint 合成拟合确实能部分恢复。

## 5. 确认：当前 panel 特征的上下文不对称

同一小型 Qwen 因果模型中，改变后面的模拟图片 B，对前面图片 A 的 hidden 影响为 0；改变 A，对 B 的影响约 `0.00894`。因此当前同一条多图输入内，较早 panel 没有看到后面的 panel，较晚 panel 却可以看见前面的上下文。

训练每轮重排中间图片时，同一图片的上下文会随展示位置变化。后续双向 set encoder 可以补充交互，但不能把进入它的向量当作与展示顺序无关的纯视觉描述。

尚需真实特征验证：这种上下文变化是否强于图片内容信号，以及 2048→256 投影与均值池化是否进一步损失线索。不要仅凭高余弦相似度认定特征无用，应同时测中心化特征、同图跨重排稳定性和可学习的小任务。

## 6. 后续实验优先级

1. **先修正信息传递再做短跑**：文字前置、显式首尾角色、输出位置条件保持可区分，逐项消融；不要用当前 last.pt 和旧优化器直接验证新结构。
2. **固定 16–32 个真实 puzzle**：冻结 backbone，缓存原始 pooled hidden，从新初始化训练 projection/decoder。记录训练是否能接近完全拟合，独立报告新重排输入上的结果；固定输入记忆能力不能代替重排鲁棒性。
3. **区分表示与排序头**：同一缓存特征比较简单拼接 MLP、当前 NAR 和稳定打分头，检查 projection 前后信息；仅仅某个头未拟合不能证明特征完全无用。
4. **验证真实特征**：改变 OCR 内容、移除 OCR、交换首尾、重排中间 panel、移除真实端点内容但保留角色，检查中间特征和预测的响应。人工 benchmark 同样需要与模型对齐图片分辨率、文字辅助及指标。
5. **优化对照**：固定 backbone 后比较 decoder lr `1e-4` / `1e-3`、warmup 和 query/key 归一化。记录行列 loss、tanh 饱和比例、梯度及参数更新，确认何时首次发生趋同。

当前 gradient accumulation 的样本归一化和 endpoint loss 截取未发现明显错误。Greedy matching 可能影响推理精度，但无法解释训练 loss 本身长期等于随机基线，优先级较低。

本地尚无本次 MangaZero 训练数据和预训练 Qwen 基础权重。真实特征能否分辨内容、LoRA 是否让特征退化、分辨率是否足够，仍待服务器实验；不应把这些假设写成已确认结论。
